# sotf-capture audit — 2026-10-18

> The original audit below describes the pre-fix working tree. The implementation follow-up at the end records the 0.6.0 corrections and subsequent verification; original locations and observations are retained as historical evidence.

This audit is based on executable source, test implementations, and local test runs. README files, design documents, changelogs, and comments claiming correctness were not treated as evidence that behavior works.

**Assessment:** the offline timing and analysis code has substantial numerical testing and several sound validation boundaries. Acquisition has materially weaker guarantees. A passing suite currently permits playback timeouts and late cancellation to produce successful measurements. CTC processing has a clock-domain error, and two file-processing APIs cross their intended session directory boundaries. These deserve correction before treating capture completion or a published CTC bundle as trustworthy.

## Security

### S1 — CTC merge permits out-of-directory file reads and disclosure in the output bundle

**Locations:** `src/capture_session/ctc.rs:328`, `:367–403`, `:409–418`.

The merge closure validates `name.file_name()`, but reads `directory.join(name)` using the original, unrestricted path. The earlier reference hash read also joins the unrestricted `reference_sweep`. Consequently `../outside-sentinel.txt`, an absolute path, or a local symlink to an outside file is accepted. The copied output is then rewritten to a harmless-looking basename. Raw-sweep and loopback members have neither a required input hash nor WAV decoding at this boundary.

**Observed:** a synthetic fragment with a normal reference and loopback, and a sentinel as its `raw_sweep`, succeeded with exit code 0 in all three cases. Each resulting bundle contained the exact sentinel bytes. No real private file was used. An attacker can therefore cause a user merging a supplied fragment to include readable private files in a bundle they later share. This is arbitrary local-file copying, not an automatic network upload.

**Correction:** validate the entire member path before any read, require a single portable relative filename, and enforce regular-file containment using one shared resolver. Reject escaping symlinks. Apply the same rule to reference, ear, and loopback files. For directories writable concurrently by an adversary, use handle-relative/no-follow opening rather than a check-then-open path sequence.

**Regression:** exercise `../`, absolute paths, escaping symlinks, and a reference outside the session; require rejection before output publication. The current merge tests use `b"wav-bytes"` as input (`ctc.rs:514–519`), so success there does not establish an audio-valid bundle.

### S2 — Legacy reprocessing trusts a serialized output path

**Locations:** `src/signal_recorder/recording_session.rs:122–126`, `:196–197`, `:254–264`.

`RecordingSession::load_from_file` accepts channel paths without validation. `reprocess_recordings` joins `channel_info.csv_path` to the session directory and passes it to the CSV writer. A relative traversal escapes the directory; an absolute path replaces the base. A symlink destination is another escape route. WAV and calibration input paths also lack a session containment boundary.

**Observed:** a valid synthetic recording with `csv_path = "../sentinel.csv"` overwrote a sibling sentinel and returned a successful channel result. The overwritten file was created solely for the audit.

**Correction:** derive output filenames from validated channel identifiers, or validate destinations against an explicit output root. Do not treat paths from imported metadata as authorization to overwrite files elsewhere. If external input/calibration paths are intentionally supported, distinguish them from writable artifact destinations.

**Regression:** import a valid session whose CSV destination traverses upward or is absolute/symlinked; confirm the outside file remains unchanged.

### S3 — Resource limits do not cover auxiliary acquisition or every import path

**Locations:** `src/capture_session.rs:514–546`, `:648–661`; `src/signal_recorder/probe.rs:289–295`; `src/signal_recorder/run.rs:205–219`; `src/signal_recorder/types.rs:277–278`, `:330–346`; `src/capture_session/ctc.rs:288`, `:328`, `:375`, `:470–487`.

Session validation limits the main sweep, but probe/anchor durations and silence gaps have only sign/finite checks. **Observed:** `plan-validate` accepted both `probe_duration_ms = 1e20` and `bass_duration_s = 1e20`. Recording subsequently converts duration to sample counts, generates whole signals, and builds full-session buffers. Checked total-byte arithmetic and a practical upper bound are missing. Huge allocation, capacity overflow, or abort can follow; the oversized allocation itself was deliberately not attempted.

CTC merging reads complete JSON and member files into memory, and its separate `read_mono_f32` collects all samples without the 16-million-frame limit or finite-sample check used by `clock::io::read_wave`. `ctc::raw_artifact` checks filename syntax but does not enforce symlink containment. Thus the better protected clock-processing path does not establish equivalent protection for CTC reads.

**Correction:** validate aggregate duration × rate × channel count before generation; use checked arithmetic and fallible allocation; impose metadata, WAV, and total-bundle limits. Reuse the bounded WAV reader and artifact resolver across paths.

## Fundamental correctness: starts, events, and completion

The implementation has several distinct acquisition protocols. Their guarantees differ:

| Property | Sweep recorder/playback | Probe/bass auxiliary path | Multi-device session path |
|---|---|---|---|
| Input readiness before output | Fixed 100 ms sleep | Fixed 100 ms sleep | At least 250 ms of actual input from every route, with deadline |
| Runtime stream error | Logged | Logged | Atomic failure checked by control loop |
| Playback deadline | Falls through into success path | Falls through into success path | Returns error |
| Dropped data | Count returned separately | Callback count logged as frames, then discarded | Fails capture |
| Poll timing | Adds nominal sleep durations | Adds nominal sleep durations | Uses `Instant` |
| End of output | Frames submitted to callback plus fixed tail | Cursor plus fixed tail | Cursor plus fixed 500 ms drain |

No path should equate callback submission with confirmed physical presentation without a declared latency bound. Fixed drain times may work on common interfaces, but do not prove completion for arbitrary buffering. This limitation was identified from the code; a hardware truncation case was not measured.

### C1 — Timeout and stream failure can become a successful measurement

**Locations:** `src/signal_recorder/record.rs:259–321`, `:455–495`; `src/signal_recorder/recorder.rs:297–299`, `:329–355`; `src/signal_recorder/playback.rs:254`, `:278`, `:301`, `:317`; `src/signal_recorder/types.rs:479–526`; `src/signal_recorder/build.rs:116`, `:218–224`.

The sweep polling loop has no terminal distinction between “finished” and “deadline expired.” It proceeds to stop, inspect samples, and analyze either outcome. CPAL error callbacks only log; neither recorder nor playback carries the error into the returned result. The auxiliary path has the same fall-through. Correlation/level checks can catch some damaged audio, but they cannot prove that playback completed or that the stream remained healthy.

**Observed:** a wrapper around `FakePlayback` allowed the wake-up to finish, then returned `false` from `is_finished()` for the measurement forever. The public `record_and_analyze_with_recorder` returned `Ok` and wrote a CSV after the deadline. Clean synthetic samples deliberately isolated the missing completion gate from signal-quality gates.

**Correction:** use an explicit terminal outcome (`Completed`, `Cancelled`, `TimedOut`, `StreamFailed`), propagate asynchronous errors out of both backends, and require successful output completion plus input continuity before analysis acceptance. Preserve partial data as failed evidence when useful. Base timeouts on a monotonic deadline, not accumulated requested sleep time.

**Regression:** output never starts delivering callbacks, output stalls midway, input disconnects after a valid prefix, and callback errors occur during drain/stop. Each must fail even if the retained samples correlate well.

### C2 — Successful stream creation is treated as input readiness

**Locations:** `src/signal_recorder/record.rs:225–245`, `:425–442`; `src/signal_recorder/types.rs:458–475`; contrast `src/signal_recorder/multi_capture.rs:460–484`.

The sweep and auxiliary paths start input, sleep 100 ms, then start output without requiring even one input frame. A device may have accepted `play()` while still warming, blocked, or disconnected. With delayed callbacks, the beginning of a measurement can be lost. Wake-up does not prove readiness of the next stream: wake-up stops its streams and the measurement opens them again.

The session path already implements the stronger condition: real frames from every input, a startup timeout, cancellation, and error checks. Its readiness condition is not shared by the other paths.

**Correction:** wait for a minimum amount of valid input on the actual measurement streams, with a deadline and cancellation, and start output only after that condition holds. Retain streams across wake-up and measurement where practical. Test callback arrival, not elapsed wall time.

### C3 — Cancellation during capture tails is lost

**Locations:** `src/signal_recorder/record.rs:294–321`, `:486–517`; `src/signal_recorder/types.rs:513–526`; `src/signal_recorder/wake.rs:169–209`.

After playback finishes, sweep capture sleeps one second and checks only the earlier local `cancelled` boolean. A cancellation set during that sleep is not read before analysis and output writing. Auxiliary capture has the analogous fixed-tail/teardown interval. Wake-up attempts have no cancellation parameter inside the attempt: a cancellation after the outer check can still be followed by `playback.start()` and waits until the attempt ends.

**Observed:** the audit wrapper set the cancellation flag 100 ms after playback completion was observed, during the one-second tail. The function returned `Ok`, with the flag true and a CSV written.

**Correction:** make waits cancel-aware, re-check before starting any audible output, after drain, and before committing success. A failed stop must not erase cancellation, but cancellation itself must not be erased by an earlier successful poll.

**Regression:** cancel before input, during input startup, before output, during playback, during tail, and immediately before publication. Check returned status, stream cleanup, and artifact state for each phase.

### C4 — CTC exports confuse stimulus time with raw input time

**Locations:** `src/capture_session/ctc.rs:103–105`, `:160–209`; `src/capture_session.rs:565–582`; `src/signal_recorder/multi_capture.rs:460–481`. Downstream: AutoEQ `crates/roomeq-workflow/src/ctc/load.rs:443–479`.

CTC assembly reads **raw** ear and loopback recordings, slices all of them with `layout.sweep_offset..layout.end_chirp_offset`, and interleaves the ears. These layout offsets describe the output stimulus; raw inputs have pre-roll and potentially different origins and rates. No fitted mapping is applied to these slices. A sufficiently delayed start can move part or all of the sweep outside the exported window; a smaller delay reduces the retained decay interval.

**Observed:** a synthetic raw session at 48 kHz placed three seconds of input silence before its stimulus. The raw sweep peaked at approximately `0.1`, but `plan-process` exited 0 and published a CTC fragment plus handoff whose ear and loopback WAVs both had peak `0.0`. Their nominal crop covered 1.10–3.35 seconds of raw input, before the first recorded stimulus at 3.50 seconds. The reference sweep remained nonzero. Processing warned that timing chirps were unavailable and marked the takes magnitude-only, yet still exported CTC. This reproduces both the wrong crop and the missing CTC eligibility gate; it does not establish the downstream consumer's response to the silent files.

Additionally, CTC plan validation requires two known ears and a loopback, but does not require a shared capture device/clock. The CLI accepted a plan with each ear and loopback on a different device. CTC assembly does not reject the differing recorded device IDs. The inspected downstream loader finds one loopback IR peak and shifts both ear IRs by that same amount. It does not repair independent ear clock origins or rates. A 10 ms inter-device origin difference remains 480 samples at 48 kHz and contaminates interaural timing.

This is distinct from ordinary acoustic propagation, which must be preserved. Aligning each ear independently to its own response peak would also be wrong because it would erase the physical delay being measured.

**Correction:** either require and verify one common hardware capture timeline for both ears and loopback, or explicitly transform all three onto a proven common timebase. Locate crop boundaries on that timebase, retain the complete sweep and required decay, and preserve physical delays. Fail export when the evidence is insufficient.

**Testing weakness:** `ctc_assembly_crops_raw_takes_into_stereo_ears_loopback_and_reference` (`clock/tests.rs:522–627`) checks lengths and asserts output samples equal raw samples at the same nominal offset. It copies a microphone recording as loopback. Those assertions encode the disputed implementation; they do not demonstrate correct recovered CTC transfer functions under startup offset or clock mismatch.

### C5 — Wake-up violates the configured output level

**Locations:** `src/signal_recorder/wake.rs:31`, `:62–88`, `:100–116`; `src/capture_session/record.rs:237–275`; `src/signal_recorder/record.rs:1490–1501`.

The wake waveform is normalized to a fixed peak of `0.5` (approximately −6 dBFS). Neither wake entry point takes the requested capture level. It precedes both ordinary sweep and planned-session capture. A user selecting amplitude `0.001` (−60 dBFS) can therefore receive a wake burst about 54 dB higher in peak level than the requested stimulus. The taper reduces edge clicks; it does not impose the user's amplitude limit.

**Correction:** apply a single explicit output ceiling to every emitted signal, including wake-up. Pass the configured level into wake generation or offer a separately declared, bounded wake level. Do not silently increase it to obtain a correlation lock.

**Regression:** intercept every emitted buffer for several low capture levels and assert wake-up, chirps, and sweeps all respect the declared ceiling.

### C6 — The acquisition journal reaches a terminal state too early

**Locations:** `src/capture_session/record.rs:322–337`, `:436–442`, `:471–478`, `:719–723`; consumer `src/capture_session/clock/io.rs:350–356`, `:444–464`.

`record_with` saves `RawComplete` when sweeps finish. `record_capture_session` then starts the declared probe and bass-anchor passes. The journal remains `RawComplete` while those passes run and while their results are saved. A crash or save failure can leave a terminal journal with a complete sweep matrix but missing declared auxiliary results. The processor accepts that status and does not require declared auxiliary passes to have succeeded before selecting the whole matrix automatically.

Handled runner failures do update the journal to `Failed`/`Cancelled`; this finding concerns the published state between phases and failures outside that handler.

**Correction:** keep acquisition nonterminal until all declared passes and their artifacts are committed. Record an explicit phase and completion bitmap, with the final terminal transition occurring once. Validate phase completeness when loading the journal.

**Regression:** inspect the on-disk journal from inside injected auxiliary runners, and inject a crash/save error between sweep completion and auxiliary completion. No incomplete declared acquisition should appear complete.

### C7 — Dropped audio is not consistently represented as invalid evidence

**Locations:** `src/signal_recorder/build.rs:199–215`; `src/signal_recorder/types.rs:432–436`, `:508–544`, `:581–588`; `src/signal_recorder/record.rs:1396–1412`; `src/signal_recorder/fake_tests.rs:583–614`.

The auxiliary callback increments `capture_overruns` by **one per overflowing callback**, then the caller logs that number as dropped **frames**. The count is not included in `PlayPerChannelOutput`, probe results, or bass-anchor results, and does not cause rejection. This loses both the quantity and location of missing audio.

There is also a normal-path capacity mismatch: the auxiliary ring holds nominal playback duration plus 0.5 seconds, is drained only after stopping, but typical capture includes approximately 0.1 seconds pre-roll, nominal duration plus 0.2 seconds before the completion break, and another 0.5 seconds before input stop. At equal rates and ordinary startup that is roughly 0.3 seconds beyond capacity. Usually this loses late tail data; additional output startup delay can move important content into the lost region. These are timing-derived bounds, not a hardware measurement.

Sweep capture returns an accurate total `dropped_samples`, but does not feed it into `build_capture_quality` or its structured findings. A caller inspecting only `quality.trustworthy` can miss known transport loss. The existing fake test reports 1,234 drops without removing samples and asserts only that the count is returned; it cannot detect the effect of a real discontinuity.

**Correction:** count actual missing frames, track discontinuity positions, drain bounded rings while capture runs, and make transport integrity part of acceptance. Tail-only loss may be handled separately only if its position is known. Propagate loss into saved provenance.

**Regression:** use real missing blocks before, within, and after the stimulus, multiple callback sizes, and consumer stalls. Assert exact counts and explicit quality/status outcomes.

### C8 — Bench calibration does not have stable acquisition provenance

**Locations:** `src/bin/sotf_capture.rs:821–829`; `src/capture_session/localization.rs:424–429`, `:2018–2034`; `src/capture_session/record.rs:505–537`; `src/capture_session/handoff.rs:106–133`, `:164–174`.

A relative localization calibration path is validated against the plan directory but later resolved against the raw capture directory. Recording snapshots microphone frequency-response calibrations, but does not snapshot this bench file. A plan can therefore validate and later process without the calibration, or load a different file with the same relative name. Absolute paths still allow later edits to change the result. The processor warns and continues uncalibrated after load failure; it does not fail closed or preserve the originally validated bytes.

The bench correction changes absolute ranges, yet the bench source file is not included in the handoff inventory. Raw loopback takes used for localization are also read from the original raw directory and are not generally retained/inventoried as raw loopback evidence by the processed bundle; CTC-derived cropped files are a different artifact.

**Correction:** resolve all calibration inputs once, freeze their exact bytes and hashes with the acquisition, and process the frozen copies. Include every artifact used for localization, especially raw loopback and bench calibration, in the retained evidence inventory.

**Regression:** use different plan/raw/output directories, mutate the original calibration after capture, move the bundle, and verify identical results from the retained inputs.

### C9 — Sweep hardware negotiation drops part of the supported configuration

**Locations:** `src/signal_recorder/recorder.rs:197–225`, `:265–268`; `src/signal_recorder/playback.rs:61–73`, `:198–240`.

`CpalRecorder` selects supported channel count and rate, then always builds an `f32` input stream. It does not select or retain the advertised sample format. A device exposing the requested mode only as integer PCM can fail despite supporting capture. Playback independently takes the maximum channel count across configurations, selects a rate, and dispatches using the **default** configuration's format. Those three choices need not form one advertised configuration.

The auxiliary and multi-device paths already have typed format negotiation. The mismatch is specifically in the sweep backend. Also, sweep/aux/session acquisition use `cpal::default_host()` while live monitoring selects the requested host; ASIO support is therefore not consistent across entry points. Sweep/aux discovery accepts first fuzzy name matches (`devices/misc.rs:68–101`), whereas session/live capture reject ambiguity.

**Correction:** select one supported tuple of host, device identity, channel count, rate, and format; build exactly that tuple. Require unambiguous device selection for measurements. Share the tested negotiation routines.

**Regression:** integer-only inputs; different formats at different channel widths; a maximum channel width unavailable at the default rate; duplicate names; explicit ASIO selectors. Hardware behavior remains to be verified on the relevant platforms.

## Performance and resource behavior

### P1 — Per-frame limits do not bound total session memory

**Locations:** `src/signal_recorder/multi_capture.rs:23–25`, `:138–169`, `:383–390`, `:426`; `src/capture_session.rs:384–385`, `:658`.

There are up to 33 inputs and up to 16,000,000 stored frames **per input**. Planar recording reservation alone can approach `33 × 16,000,000 × 4 = 2,112,000,000` bytes. Each device group also gets a one-second ring whose item is `[f32; 33]`, even for a one-channel device. With 33 independent groups at 384 kHz, rings reserve another `33 × 384,000 × 33 × 4 = 1,672,704,000` bytes. The combined upper scale is roughly 3.8 GB before stimulus copies and analysis workspaces. The stricter plan duration budget slightly reduces the attainable planar maximum but does not change the conclusion.

Callbacks additionally initialize and enqueue all 33 float slots for each frame regardless of selected channel count. `try_reserve_exact` improves allocation error handling for planar vectors, but it does not impose a total memory budget, and ring allocation follows a different path.

**Correction:** account for total bytes across inputs and groups before opening devices. Size ring storage to the group's actual width or use bounded interleaved blocks. Stream large raw takes to disk while retaining bounded capture buffers. Add tests around the total-budget boundary and measure RSS at supported maximum configurations.

### P2 — Auxiliary playback allocates all silent channels for the entire sequence

**Locations:** `src/signal_recorder/types.rs:330–346`.

The probe/bass path creates one full-length vector for every hardware output channel and then creates an interleaved copy. Only one output is active at a time. Memory therefore scales with hardware channel width × number of tested outputs × segment length, with both representations live during interleaving.

For 64 outputs on a 64-channel stream, 48 kHz, two-second tones and 500 ms gaps, `total_frames = 48,000 × (0.5 + 64 × 2.5) = 7,704,000`. Each representation occupies approximately 1.97 GB; their combined construction peak is approximately 3.94 GB before input capture and analysis. These are direct allocation calculations, not measured RSS.

**Correction:** retain one mono signal and a compact segment/routing schedule. Fill each callback from that schedule, zeroing inactive channels in the callback buffer. The multi-device path's output overrides demonstrate a suitable existing approach.

### P3 — Rate limiting does not make callback logging realtime-safe

**Locations:** `src/signal_recorder/recorder.rs:285–299`; `src/signal_recorder/build.rs:209–224`; `src/signal_recorder/playback.rs:254`, `:278`, `:301`; `src/rate_limit.rs:10–14`, `:44–48`.

On overflow/error, audio callbacks invoke the installed logger. The rate limiter bounds frequency, but the selected log call can format and perform synchronized or blocking output. Its clock origin also uses lazy `OnceLock` initialization. Under overload, this adds work to the callback that is already failing to keep up. No callback deadline measurements were taken, so this is a verified realtime hazard rather than a measured dropout rate.

**Correction:** callbacks should publish counters and compact error codes only; control-thread polling should format and log them. Preinitialize any shared timing state before starting audio. Test with an intentionally slow logger and a callback watchdog.

### Additional performance observations

- Repeated sweep analysis keeps raw and corrected copies, deconvolves for averaging, writes a WAV, and reads/analyzes that WAV again (`record.rs:1009–1062`, `:1109`, `:1236–1291`). Profile this before attempting micro-optimizations; avoid unnecessary copies and reuse in-memory analysis where feasible.
- The fake room renderer uses direct nested-loop convolution (`fake.rs:622–631`). The integration fixture uses a 24,000-tap modal response at 48 kHz (`tests/emulated_capture.rs:595`). This is useful physics coverage, but the integration suite took **192.41 seconds** in the debug test profile, with this test the last outstanding case. Keep a small independent direct-convolution oracle; use a faster independently verified fixture-generation path or appropriate optimized test profile for long responses. Do not weaken its numerical assertions merely to shorten the suite.
- Production performance cannot be inferred from those debug test times. No release-mode comparison, allocator profile, or hardware throughput benchmark was performed.

## Test quality

### What the tests establish well

There is meaningful coverage beyond serialization and smoke tests:

- Clock fits use an independent first-order-hold sampling oracle rather than the production resampler (`capture_session/clock/tests.rs:69–81`), including offsets, skew, physical propagation, missing markers, and unavailable survey evidence.
- Localization tests exercise ambiguity/refusal, reflections, unsurveyed geometry, repeat aggregation, inverse/joint solves, and known positions. These are stronger than simply asserting a solver returned a value.
- Emulated integration tests check microphone calibration, noise/distortion, channel-specific room responses, clipping, and analytically expected comb/modal behavior.
- Multi-device callback cores are tested for variable block boundaries, integer conversion, output routing, overflow, malformed frames, and non-finite samples (`multi_capture_tests.rs:150–247`).
- The main raw-processing boundary tests traversal and calibration mutation. Capture record tests verify calibration preflight and preservation of already completed sources on cancellation.
- Live-level capture tracks sample sequence gaps and invalidates affected frames (`live_level.rs:408–435`). This is a useful existing model for measurement discontinuity tracking.
- Wizard helpers test generation comparison and batch decisions. This establishes the helpers' behavior, not the correctness of all asynchronous frontend callers in other repositories.

### Where confidence is overstated

1. **No realistic asynchronous transport in the fakes.** `FakePlayback::start` marks all frames rendered immediately (`fake.rs:290–299`); `FakeRecorder` creates complete audio when stopped and derives progress from the signal rather than callbacks. It cannot model callbacks starting late, pausing, failing, or racing with stop. The audit's two simple wrappers demonstrated defects that the passing suite missed.
2. **Multi-device orchestration itself is not simulated.** Pure callback tests are useful, but session tests replace the entire `capture_multidevice` operation with a closure returning complete vectors (`capture_session/record/tests.rs:28–58`). They bypass startup barriers, deadlines, final drain, and partial multi-stream failure cleanup.
3. **CTC assertions do not validate recovered timing.** The test checks raw index equality and output dimensions, with a copied microphone serving as loopback. It needs a separate ground-truth electrical reference and known physical ear delays, tested through the downstream loader.
4. **Sample-drop tests are bookkeeping-only.** Injecting a drop count while leaving every sample intact cannot expose timeline corruption or validate the quality verdict.
5. **Security tests cover one resolver, not all import APIs.** Main-session traversal coverage did not protect CTC merge or legacy reprocessing. Each public file-processing entry point needs adversarial path, symlink, size, and partial-output cases.
6. **No enforced callback/allocation performance evidence was found.** No tracked local benchmark/fuzz tree or property-test harness was found in the inspected repository. This does not establish the absence of parent-repository CI. Current deterministic tests need schedule/fault variation, resource-bound cases, and callback deadline checks.
7. **A real-recording regression is optional and locally supplied.** `signal_recorder/tests.rs:3185–3187` ignores `fireface_sweep_lock_local_regression` unless a local WAV is supplied. Its absence limits claims about current hardware behavior.

The highest-value addition is a deterministic transport simulator with a virtual monotonic clock and explicit events: stream opened, first input block, output submitted, output presented, error, dropped interval, cancellation, drain complete, and stream released. Exercise the same production orchestration with it. Randomized event schedules should check that no failure/cancellation reaches a successful terminal state and that every started stream is released exactly once.

### Pre-existing working-tree change: unknown distortion becomes measured zero

**Location:** `src/recording_helpers.rs:655–702`, added before this audit.

`enrich_results_from_take_csvs` maps non-finite THD entries, including the CSV's explicit unavailable marker, to `0.0`. This converts unknown distortion into a numerical claim of zero distortion in the restored result. Its new test explicitly expects that conversion. Separately, the early return when THD and RT60 already exist skips restoration of missing clarity/group-delay fields; the frequency match also lacks an explicit finite-value check.

Preserve an unavailable mask or represent gaps at the visualization boundary, and check each restored metric independently. Tests should distinguish measured zero from unavailable evidence and include partially populated results. This observation applies to the uncommitted helper, not necessarily to the audited HEAD alone; it was left untouched.

## Repair priorities and acceptance criteria

1. **Close file boundaries:** shared contained input/output handling for CTC and legacy sessions; adversarial path and size tests at every public entry point.
2. **Make acquisition outcomes explicit:** readiness on actual streams, callback error propagation, monotonic deadlines, cancel-aware tails, transport-loss gates, and one terminal journal transition after all declared passes.
3. **Fix CTC timebase eligibility and cropping:** require verified common clocks or perform explicit clock mapping; verify recovered physical ear delays through the consumer, including slow startup and skew cases.
4. **Apply the user's level to all output:** wake-up must obey the configured ceiling, with buffer-level assertions.
5. **Bound total resources and retain evidence:** byte budgets, scheduled auxiliary playback, frozen bench/loopback artifacts, and complete discontinuity provenance.
6. **Strengthen testing at the seams:** deterministic asynchronous transport, mid-phase failure injection, crash/publication tests, real hardware qualification, and release-mode memory/callback benchmarks.

The existing numerical tests are worth preserving. The principal missing guarantee is that successful numerical analysis follows a complete, continuous, correctly timed, authorized acquisition—and that failure or cancellation remains visible all the way into saved artifacts.
